# **โปรโตคอลการทำงานทีละสเต็ป (Step-by-Step Protocol)**

## **1\. กฎการเริ่มต้นสเต็ป (Pre-Execution Gate)**

* ตรวจสอบว่าโมดูลก่อนหน้าผ่านการทดสอบ 100% แล้วเท่านั้น ห้ามข้ามขั้นตอน  
* ทำการสร้าง Snapshot สำรองข้อมูล (Backup Checkpoint) ก่อนเริ่มแตะต้องโค้ด

## **2\. กฎการทดสอบหน้างาน (Verification & Testing Rule)**

* ทุกไฟล์หรือฟังก์ชันที่สร้างใหม่ ต้องมีไฟล์ทดสอบควบคู่เสมอ  
* ต้องรันเทสต์ผ่าน 100% และไม่มีผลข้างเคียง (No Side Effects) ต่อระบบเดิม

## **3\. วงรอบการจัดการข้อผิดพลาดและซ่อมแซมตัวเอง (Self-Healing Loop)**

* **เมื่อพบ Error หรือเทสต์ไม่ผ่าน:**  
  1. **Immediate Rollback:** สั่งถอยรหัสย้อนกลับไปยังจุด Snapshot ทันที เพื่อให้ระบบหลักกลับมาปลอดภัย 100%  
  2. **Lesson Learned Capture:** สกัดสาเหตุของบั๊ก บันทึกลงในฐานความรู้ `CLAUDE.md` / `shared_memory.json`  
  3. **Adaptive Retry:** วิเคราะห์หาวิธีการใหม่ที่ไม่ซ้ำกับข้อผิดพลาดเดิม แล้วเริ่มทดสอบใหม่อีกครั้ง  
  4. **ทำซ้ำอย่างต่อเนื่อง:** จนกว่าจะผ่านเกณฑ์ แล้วจึงบันทึกสถานะของ Roadmap เป็น "สำเร็จ" ก่อนไปสเต็ปถัดไป

## **1\. การแบ่ง 2 โหมดการทำงานของระบบ (Dual-Mode Architecture)**

### **🟢 โหมดที่ 1: Active Interactive Mode (โหมดรับใช้ลูกพี่ \- Priority 0 สูงสุด)**

* **สถานะ:** ทำงานทันทีเมื่อลูกพี่สั่งการ (พูดด้วยเสียง, พิมพ์แชท, ใช้งานผ่านมือถือ/เดสก์ท็อป)  
* **พฤติกรรม:** ระบบจะหยุด (Pause/Yield) งานประมวลผลเบื้องหลังทั้งหมดทันที เพื่อทุ่มทรัพยากร CPU/GPU/RAM มาตอบสนองและช่วยเหลือลูกพี่ด้วยความเร็วสูงสุด

### **🔵 โหมดที่ 2: Idle Self-Evolution Mode (โหมดพัฒนาตัวเองช่วงเครื่องว่าง / Dream Cycle)**

* **เงื่อนไขทริกเกอร์:** ทำงานอัตโนมัติเมื่อระบบตรวจพบสภาวะ **"User Interaction & Activity Stream Idle"** คือเมื่อว่างเว้นจากการสั่งงานของลูกพี่ หรือช่วงที่กระแสคำสั่งเริ่มนิ่ง โดยไม่จำเป็นต้องรอให้เครื่องคอมพิวเตอร์ว่าง (Hardware Idle) เนื่องจากลูกพี่มีการใช้งานเครื่องตลอดทั้งวัน ระบบจะอาศัยช่วงจังหวะที่ไม่มีการปฏิสัมพันธ์ใหม่เพื่อสลับมาหยิบงานจาก Roadmap ไปทำต่อทันที  
* มาตรการ Background Resource Capping: กำหนดให้งานเบื้องหลังทั้งหมดรันในรูปแบบ Low-Priority / Background Worker เพื่อจำกัดการใช้ทรัพยากร ไม่ให้รบกวนหรือแย่งประสิทธิภาพการประมวลผลในขณะที่ลูกพี่กำลังใช้งานหรือเล่นคอมพิวเตอร์อยู่  
* **พฤติกรรมการทำงาน (The Autonomous TDD Loop):**

  3. **เขียนโค้ดและ Unit Test ควบคู่กัน:** ลงมือสร้างฟังก์ชันและไฟล์ทดสอบ  
  4. **วนลูปจนกว่าจะผ่าน (Iterative Self-Healing Loop):**  
     * รันการทดสอบจริง 100%
